Sikkerhet må være gjennomgående. FEIDE/Entra ID er planlagte identitetskilder; autentisering må skilles fra autorisasjon. Dataklassifisering styrer hvilke modeller, tjenester, lagre og integrasjoner som kan brukes. Alle utleveringer, ikke bare primærmodellkallet, omfattes.

Kubernetes med mikrosegmentering, begrensede tjenestetilganger og ekstern vedvarende lagring er målbildet. Memory Fabric skal ikke være direkte eksponert; backend er den planlagte inngangen. Prinsippet om minste privilegium gjelder også connectors.

Menneskelig godkjenning trengs for handlinger med vesentlige konsekvenser. Toolserver håndhever regler uavhengig av modellens output. Dokumenter og tool-resultater er potensielt upålitelige data, ikke instruksjoner. Beskytt mot prompt-injeksjon og utlevering.

Sporbarhet krever hendelseslogger, versjonering og begrenset tilgang. Unngå unødvendige personopplysninger og hemmeligheter i logger. Definer livsløp, sletting, beredskap, test og evaluering. Lokal modellkjøring alene gjør ikke behandling av røde eller svarte data lovlig eller sikker.

ROS, DPIA der det er påkrevd, og godkjenning inngår i styringen av konkrete behandlinger.

Innebygd personvern omfatter identitetsseparasjon, dataminimering, PII-vask og kontrollert modellruting. Dette er beskrevet nærmere i [Innebygd personvern](./personvern.mdx).

Sikkerhetsarkitekturen omfatter også [isolerte kjøremiljøer](./kjoremiljo.mdx), [obligatoriske evals og kvalitetsporter](./evaluering.mdx) og [audit, tracing og KI-forordningen](./sporbarhet.mdx). Tilgang til logger, testdata og produksjonsepisoder styres separat fra tilgang til selve agenten.
